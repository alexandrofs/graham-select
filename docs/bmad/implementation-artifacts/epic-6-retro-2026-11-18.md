## ❌ 3. Desafios, Causas Raiz & Aprendizados Críticos

### 3.1 Desalinhamento entre API e UI (Prioridade 1 definida pelo Project Lead)
- **Sintoma:** Toda a pilha de exclusão de ticker (`deleteTicker`) foi construída no backend e no provider Flutter na Story 6-3, mas a tela `AdminTickersPage` só expôs os botões "Editar" e "Invalidar Cache".
- **Causa Raiz:** Critérios de aceite focados isoladamente em endpoints de API sem amarrar a jornada completa na interface, gerando código órfão.
- **Lição:** Exigir paridade estrita entre API e UI no Definition of Done. Funcionalidades expostas em controllers de negócio devem possuir superfície correspondente na tela ou descopo explícito aprovado antes da implementação.

### 3.2 Testes em H2 Mascarando o Ambiente Real de Runtime
- **Sintoma:** Testes unitários e de integração passavam com sucesso, mas a aplicação quebrava na inicialização em perfil `local` por migration alterada e propriedade faltante.
- **Causa Raiz:** O `@DynamicPropertySource` em classes base de teste injetava propriedades que não existiam no `application.yml` de produção, e testes em H2 limpo não detectavam quebras de checksum de bancos já migrados.
- **Lição:** Regra estrita de imutabilidade em migrations Liquibase (sempre novas migrations compensatórias idempotentes) e smoke tests de startup real com validação do `application.yml`.

### 3.3 Tendência Crescente de Retrabalho em Code Review (4 → 11 → 12 patches)
- **Sintoma:** Volume de correções solicitadas no review cresceu a cada história do épico.
- **Causa Raiz:** Autoverificação pré-review insuficiente antes de submeter código (ex.: adapter sem persistência real).
- **Lição:** Checklist de pré-submissão obrigatório pelo desenvolvedor validando ponta a ponta persistência e tipagem entre camadas.
